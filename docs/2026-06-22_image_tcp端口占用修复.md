# 2026-06-22 image_tcp 端口占用修复

## 现象

```text
OSError: [Errno 98] Address already in use   # Manjaro 127.0.0.1:8767
RuntimeError: image tcp server exited (code 1)
```

## 根因

| 环节 | 说明 |
|------|------|
| 上次 smoke | `ImageTcpBridge` 经 SSH 在 Manjaro 起了 `image_tcp_server` |
| 异常退出 | Ctrl+C / 报错时 `env.close()` 未执行 → 远端进程仍占 **8767** |
| 再次 smoke | 新 server `bind()` 失败 → bridge `start()` 抛错 |

`image_tcp_server` 设计为**单连接**（`accept()` 一次），进程不退出则端口一直占用。

## 修复

`python3.x/image_tcp_bridge.py`：

1. **`start()` 前**：`fuser -k` 释放 Manjaro `remote_port`（8767）与 Ubuntu 本地 `local_port`（32087）
2. **`stop()` 后**：再清一次远端 8767，避免残留

## 验证

```bash
cd ~/hil-serl/examples/experiments/aubo_pick_cube_real
./smoke_env.sh
```

不应再出现 `Address already in use`。

若 `fuser` 不存在（极少），Manjaro 手动：

```bash
ss -tlnp | grep 8767
kill <pid>
```

## 优劣势

| | |
|--|--|
| **优势** | 无需手动清进程；重复 smoke 可自愈 |
| **风险** | `fuser -k` 会杀掉该端口上任意进程（本场景仅 image server） |

**置信度**：高（日志明确 `Errno 98` on bind）。
