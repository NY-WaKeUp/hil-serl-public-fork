# 鱼眼相机：你对数据做了什么「加强」？

## 直接结论

**代码里目前没有专门为鱼眼/wrist 写额外的数据增强。**  
训练时 `front` 和 `wrist` 用的是**同一套**默认增强：`batched_random_crop(padding=4)`。

文档里**建议**加 RSA（Random Scale Augmentation），但 **尚未落地到 `data_augmentations.py` / `launcher.py`**。

---

## 实际已做的（与鱼眼相关）

| 类别 | 内容 | 是否算「数据加强」 |
|------|------|------------------|
| **双相机观测** | `front`（agentview，fovy≈55° 针孔）+ `wrist`（wrist_cam，fovy=130° 广角） | 是架构/观测设计，不是 aug |
| **独立编码器** | `encoder_front` + `encoder_wrist` 各一套 ResNet10，256 维后再 concat | 是模型结构，不是 aug |
| **统一 resize** | 两路都 → 128×128 RGB 进 policy | 预处理，不是 aug |
| **无畸变矫正** | pipeline 不做 undistort / 内参标定 | 无 |
| **仿真对齐** | MuJoCo `wrist_cam` fovy=130，近似真机广角/鱼眼 FoV | sim 侧配置，不是训练 aug |
| **真机预留** | `REALSENSE_CAMERAS["wrist"]` 占位 `REPLACE_WRIST_FISHEYE_SERIAL` | 配置占位，未接驱动 |

## 训练时真正跑的数据增强

```python
# serl_launcher/serl_launcher/utils/launcher.py — make_batch_augmentation_func
for pixel_key in image_keys:  # ["front", "wrist"] 两路相同
    batched_random_crop(observations[pixel_key], rng, padding=4, num_batch_dims=2)
```

即：**±4 像素随机裁剪**，对 front / wrist **一视同仁**。

BC 路径（`bc.py`）同样只有 `batched_random_crop(padding=4)`。

`data_augmentations.py` 里虽有 color jitter、高斯模糊、solarize 等函数，但 **hil-serl 默认 launcher 没用上**，只用了 random crop。

## 文档里建议过、但未实现的

来自 [`.specstory/history/2026-06-21_鱼眼相机可行性分析.md`](.specstory/history/2026-06-21_鱼眼相机可行性分析.md)：

### RSA（Random Scale Augmentation）

- **目的**：缓解鱼眼的 **尺度过拟合**（网络死记「物体占多少像素 → 手伸多远」）
- **做法**：训练时随机 scale 0.7–1.3，再 pad 回 128×128
- **状态**：仅文档 + 示例代码，**仓库未合并**

## 若你要「为鱼眼真正加强数据」，缺的是哪一步

1. **实现 `batched_random_scale`**（或 per-key：仅对 `wrist` 开 RSA）
2. **在 `make_batch_augmentation_func` 里**对 `image_keys` 分支处理
3. **（可选）** demo 采集时多背景/光照/物体位姿，配合 RSA 泛化

当前 demo pkl 里 wrist 图像已是 130° 广角 sim 渲染，但 **训练阶段没有额外加强**。
